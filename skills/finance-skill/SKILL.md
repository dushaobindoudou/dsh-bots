## 红线（金融场景一票否决）

- **禁止编造数据**：不虚构数据/事件/公司名/财务数字；数据源缺失时直接说明"当前数据源未覆盖 / 需进一步核实"，不要编一组数据再加"待核实"标签；引用不确定的研报/论文时标"该引用需核实原文"
- **查不到≠不存在**：检索/取数没有结果时只能说“未查到”并列出已尝试的检索词、代码和通道，**不得据此断言“未上市/不存在/仍是概念”**；不得穷举号段猜代码（先 `data_bus.py search --name`）
- **只用返回的字段**：不得用一个字段推算或冒充另一个指标——成交额 `amount` 不是市值，市值只用 quote 返回的 `market_cap`（为 null 就说明数据源未提供）；同行/其他 Bot 的结论是待核实的说法，不是证据
- **指标口径统一并注明**：MA/MACD/RSI 等优先用 `<skill目录>/scripts/price-action/basic_indicators.py` 的实现（RSI 为 Wilder 平滑）；自写计算必须注明公式与窗口，不同算法的数值不得混用或互相比较（同一 RSI14，简单平均与 Wilder 平滑可差一倍，“极度超卖”与否随之改变）
- **用户纠正时重新取数**：用户指出“已经上市/数据不对”时，先用工具重新核实再回答，不得复述之前的结论
- **禁止核心概念混淆**：客户 vs 竞争对手、整机厂 vs 零部件厂、净利润 vs 归母净利润、同比 vs 环比、财年 vs 自然年；不确定时用"据我理解"前缀并请用户确认
- **禁止数据自相矛盾**：同一回答内数据与结论必须一致；多组数据先交叉校验；数据源冲突时优先采信高层级来源（交易所、公司公告、年报）并显式标注分歧
- **强制免责声明**：所有包含具体投资建议、操作价位、买卖判断、仓位调整建议的输出，必须在回复末尾附加以下免责声明（固定文案，禁止改写、缩减或省略）：

  > **免责声明**：以上内容基于公开数据和量化分析，仅供参考，不构成投资建议。市场有风险，投资需谨慎。任何投资决策应结合个人风险承受能力、资金状况和投资目标独立判断，必要时咨询持牌专业机构。过往表现不预示未来收益。

## 数据获取（三条通道，按序降级）

所有行情、财务、宏观和技术指标**必须动态获取并标注来源和时点**，禁止凭训练记忆输出数字；记忆中的数字只能作 sanity check，不能作答案。

1. **单点数据 → 直接调 `scripts/data_bus.py`**（用可用的 Shell/Bash 执行；腾讯行情无外部依赖，财务等用 akshare）：只有公司名时先 `python3 <skill目录>/scripts/data_bus.py search --name <公司名/英文名>` 取得数据源给出的代码；再 `python3 <skill目录>/scripts/data_bus.py normalize --code <代码>` 确认市场路由，再按需调 quote / kline / financial / fundflow / news / etf / index / board；任意 akshare 函数可用 `call` 逃生舱。用法见 `references/data-bus-runbook.md`（**调用前先读它**，不要凭记忆拼函数名和参数）。
2. **宽泛研究意图 → 多步检索**：有可用委派工具时可委派；没有时由当前 Bot 按手册串行检索，不能因为缺少 subagent 停止取数。以下委派约定仅在工具可用时应用。**委派 subagent 多步检索**（模拟 domain_search 模式）：委派 query 必须是"一句话检索意图"，只交代①标的/主题/范围（带代码）②大方向查什么；禁止拆成字段清单/表格格式/维度列表，禁止要求"全面/详细/深入"——subagent 自己按 `references/data-bus-runbook.md` 拆步骤。字段筛选、表格化、排序、深度分析都是主 agent 拿回数据后的活。反例："全面分析银河电子，覆盖主营业务/财务/估值/资金流/研报/公告 7 个维度"；正例："研究 A 股银河电子（002519）的整体情况"。
3. **兜底 → web_search / web_fetch**：数据源覆盖不到时检索公开信息，明确告知来源并说明非实时性；WebSearch 结果标媒体名+日期，属"非一手来源"。

**检索结果时效校验**：核对统计周期/发布时间是否满足用户"最新/今年"等要求；当前周期未发布时用最近已发布周期并说明截止时间；取不到就声明数据缺口，不得把历史数据说成当前数据。

## 执行环境与成功条件

- 以本 SKILL.md 的所在目录为 `<skill目录>`，脚本和 references 均从这里定位；禁止假设只有某个 Bot 或特定绝对路径能用。
- `quote/kline/index` 只需 Python 标准库；依赖数据接口时使用 `requirements.txt` 配置可用环境，并始终以该解释器执行。
- 只接受退出码 0 且 `ok=true` 的数据。数据时间与抓取时间分开记录，按返回的 currency、amount_unit、volume_unit 解释数值；港美股默认按延时处理。
- 某接口不覆盖、空表或请求口径无数据时报告缺口并切换有来源的通道。没有 web_search 时使用可用 WebFetch/Shell 获取一手公开披露，不能编造结果。

## 数据底线

- **前提显式**：问操作类问题（买/卖/加仓/减仓/换股）先列前提（市场环境+风险偏好+资金量/期限），缺失时主动追问而非直接给建议
- **来源+时点可追溯**：每个关键数字附近都能追到"来源+时点"（YYYY-MM-DD 或 YYYYQn）；同表共享来源/周期/口径时可在表头表尾统一标注
- **来源质量分级**：一手来源（交易所公告、统计局、年报/季报、央行/监管）可直接采信；非一手（财经媒体、研报引用、第三方二次引用）必须标"需核实原文"，研报另标机构+时间
- **先核对标的身份**：公司名/港股代码/美股代码/ADR/ETF/同名公司先确认，避免混用；港股 5 位代码可能是 ETF/杠杆产品/牛熊证，查 NAV 前先确认产品类型

## 时间口径（跨时区/跨市场必查）

- 回答"现价/最新/今天"前先判断交易状态；不在时段内必须标"盘前/盘中/盘后/休市"和最近一次 close
- 美股时间按当前日期推导 DST（夏令时开盘≈北京 21:30，冬令时≈22:30），不要硬记切换日
- 事件时点本地+北京双标，并注明盘前/盘后（如苹果 FY25Q1 财报 = 2025-01-30 美东盘后 16:30 ≈ 北京 2025-01-31 05:30）
- "今天/昨天/本周"默认北京时区；跨市场联动先对齐窗口（A 股 T 日收盘 ≠ 美股 T 日盘）
- 跨市场财报同期对比按自然年季度对齐或用 TTM 滚动 4 季，方法见 `references/peer-comparison.md`

## 使用指南

1. **识别意图**：分清"取数据"（→ 上面三条通道）还是"方法论/分析"（→ 读对应 reference 跑 scripts）；多数请求两者都要
2. **进入后必须匹配 reference，不要只读本文件就答**：把问题拆成场景标签，每个主场景加载核心 reference（多场景并行读）：

   | 问题场景 | 核心必选 | 条件追加 |
   |---|---|---|
   | 市场展望/大盘 | market-state + macro-transmission | 主线加 market-mainline；轮动加 sector-comparison |
   | 个股全面分析 | stock-deep-research + valuation-pricing | 按需加 business-model / quality-growth / peer-comparison / industry-chain |
   | 技术指标/形态 | price-action-tools | 突破/VCP 加 breakout-patterns |
   | 红利/分红/回购 | dividend-buyback | 估值加 valuation-pricing；现金质量加 quality-growth |
   | 政策/题材/热点 | policy-impact | 主线加 market-mainline；产业映射加 industry-chain |
   | 订单/合同负债 | earnings-preview + quality-growth | 收入模式加 business-model |

   完整 46 篇索引：个股研究/财报事件/交易持仓/板块主线/资金机构/宏观政策/技术分析/风险量化/衍生品跨资产/投行建模/日常 routine，按文件名见 `references/` 目录；`html-report-style.md` 只管输出格式，产出 HTML 前最后读
3. **优先用 scripts/ 现成工具**：`scripts/price-action/` 7 个技术分析引擎（K线/谐波/波浪/缠论/一目/SMC/基础指标）、`scripts/quant/` 6 个量化引擎、`scripts/ib/` 2 个投行工具。先 Read 看输入约定再 Bash 执行，不要重写算法
4. **输出规整三道校验**：每个标的必带标准代码（A股 6 位/港股 5 位/美股 ticker）；排序分层必须给可量化依据；条件范围逐个核对剔除不符标的
5. **置信度分层**：高置信直接断言；中等用"倾向于/大概率"；低用"不排除/有可能"，不要平铺 N 种可能让用户自选
6. **HTML 呈现**：分析/对比/研报类默认产出 HTML 文件（浅底深字研报风、首屏结论先行、ECharts 骨架），写完必须 `node --check` 或等价方式做 JS 语法自检；简短 Q&A 用 Markdown。风格细则见 `references/html-report-style.md`
7. **数据返回后必跑 5 维反思**：①纵向再追一个为什么 ②横向看上下游/竞对 ③时间放 3-5 年分位 ④反面找最薄弱假设 ⑤行动给条件化决策；五维都无增量才收尾
8. **有观点 + 反向声音**：分析类必须给推演后的判断；主动点出"市场已定价什么、还没定价什么"，必要时给反向声音，不要顺着用户一路点头
